## 2026-03-31 - Compounded Per-Record Access Check Overhead in SQLite
**Learning:** In `server.ts`, list endpoints (such as `/api/tasks`, `/api/documents`, `/api/rfis`, `/api/submittals`, `/api/punchlist`) execute `canAccessRecord` for every retrieved row. `canAccessRecord` invokes `canAccessProject`, which executes a query against `project_companies` if the user belongs to a company (`SELECT 1 FROM project_companies WHERE project_id=? AND company_id=?`). Without composite B-tree indexes, fetching N records results in N full table scans of `project_companies` and `record_owners`.
**Action:** Always maintain B-tree indexes on `project_companies(project_id, company_id)`, `record_owners(module, user_id)`, and `table(project_id)` for core entity tables (`tasks`, `documents`, `rfis`, `submittals`, `punchlist`, `work_packages`) to ensure O(log N) index lookups during permission evaluations and list queries.
