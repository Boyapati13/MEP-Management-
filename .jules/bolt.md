## 2026-09-20 - Missing Foreign Key Indexes on SQLite Domain Tables
**Learning:** SQLite tables defined in `initDb()` (`tasks`, `rfis`, `submittals`, `punchlist`, `dailylogs`, `documents`, `costs`, `boq_items`, `change_orders`, `purchase_orders`, `safety_incidents`, `inspections`, `dependencies`, `procurement_items`, `material_requests`, `risks`, `ncrs`, `commissioning_tests`, `handover_items`, `plan_buckets`, `plan_tasks`, `plan_task_checklist`, `audit_logs`, `notifications`, `task_status_history`) lacked database indexes on `project_id`, `user_id`, and `task_id`. This caused every API endpoint (`/api/dashboard`, `/api/portfolio`, `/api/search`, `/api/notifications`, `/api/:table`) to perform full table scans (`SCAN TABLE`), resulting in linear performance degradation as table size grew.
**Action:** Always ensure database indexes are created on foreign keys and frequently filtered columns (`project_id`, `user_id`, `task_id`) when setting up SQLite schemas in `initDb()`.
